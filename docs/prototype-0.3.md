# Prototype 0.3 — Observer Station

## 体验目标

让观众从画面外的观看者成为拥有视线、镜头、时钟和发信动作的观测者。没有任务目标、剧情触发或角色对白。沿用 0.2 的视觉核心，把体验建立在三件事上：选择怎么看、决定在哪里停留、等待自己发出的信号回来。

## 操作

1. 在视窗内拖动，或先聚焦视窗再按方向键，改变第一人称视线。Home /「回正视线」恢复核心跟踪。
2.「定点观测」停住平台位置；再次点击「继续航行」从停下的轨迹相位继续。吸积盘、时钟和信号不会随平台停住。
3. 调节光学倍率 1.00×–1.60×，通过视场改变实现光学放大。平台位置保持不变。
4.「发射探测脉冲」向固定信标 B-01 发信。等待发射 → 信标应答 → 回波抵达；一枚脉冲在途时按钮禁用。
5. 比较参考钟 t、本地钟 τ、累计时间差，以及一次信号往返分别由两种时钟记录的耗时。

信标标记固定在世界坐标 [5.5, 2.2, 0]，随视角投影；离开画面后隐藏，并显示「视野外」。这是导航标注，不是发光的天体，也不要求用户瞄准才允许发信。

## 保持视觉质量的方式

没有修改 0.2 的 GLSL、吸积盘参数、HDR/Bloom/SMAA/ACES 输出链或质量档。默认仍为 target，开发 GPU 不触发自动降质。ObserverRig 在用户未操作时重现原来的位置、朝向与镜头轨迹。

为了给仪器留出下方空间，投影主点从画面高度的 50% 移到 42%，画布与绘制缓冲区保持完整分辨率。准星与主点对应；仪器视场读数从投影矩阵的上下边界射线夹角计算。放大镜头允许局部盘面出框，这是主动近距离检查，不降低采样质量。

## 时钟模型与科学边界

本地钟沿指定轨迹进行积分：

    f = 1 − Rs/r
    vr = v · r̂
    vt² = |v|² − vr²
    dτ/dt = √[ f − vr²/(c²f) − vt²/c² ]

该表达式由 Schwarzschild 度规沿给定世界线代入得到，依据 [MIT 8.286，Problem Set 6，Problem 3](https://ocw.mit.edu/courses/8-286-the-early-universe-fall-2013/1850f16966f327416bd0658a81d11ca8_MIT8_286F13_ps6.pdf)。静止时退化为 √(1−Rs/r)。数值积分使用相邻速率的梯形法；按整条 180 秒轨迹比较 30 与 120 FPS，误差小于 10⁻⁵ 模型秒。

模型取 Rs=1 u、c=4 u/s。XYZ 是将面积半径球坐标映射到三维表示后的坐标，速度是参考坐标时间的导数；这里的 u 与 s 未映射到现实天体尺度。原有阴影几何半径 1.24 u 不等同于事件视界或真实黑洞阴影半径。轨迹由镜头设计决定，属于受控、可加速的平台轨迹，不是自由落体或测地线求解。输入不满足类时条件时明确报错，避免把无效值静默夹成合法物理结果。

时间显示的是模型中的 t 和 τ，不模拟观众接收到远方钟表光学影像的过程。切到后台会暂停整个实验，回来不补算后台时间。

## 信号模型与因果可见性

信号实验独立采用恒定坐标速度的平直传播：单程时间 = 两点欧氏坐标距离 / c。信标在收到后等待 0.4 参考秒再应答。返程每帧检测扩张波前是否到达当前接收者，对抵达时刻用二分法求解；帧内接收者位置与本地钟使用线性插值。

这是等待与往返测时的实验，不是统一的相对论通信解。未计算弯曲光路、Shapiro 延迟、频率偏移、多条光路、介质遮挡或束向天线。时钟与信号共享参考时间和模型坐标，但采用不同层级的近似。

在途状态和进度条是模型预测。远端「收到 / 回传」日志在回波真正抵达本地后才显示；日志中的时间为远端事件的参考坐标时刻。一枚脉冲在途时不能重发，避免状态混乱；事件缓存最多 12 条，不会随运行无限增长。

## 架构与扩展点

沿用 App / RendererHost / FrameClock / BlackHoleScene / ShaderManager / RenderPipeline。新增模块没有额外依赖：

| 模块 | 职责与替换边界 |
| --- | --- |
| observer/ObserverRig.ts | 原轨迹相位、定点、视线偏移、光学倍率；输出现有 ObserverState |
| observer/ObserverInput.ts | 限定视窗的 Pointer Events 与键盘输入；不全局劫持快捷键、不锁定鼠标；统一释放监听器 |
| observer/models.ts | ClockModel、PropagationModel、ObservationEvent 契约；当前 SchwarzschildClock / StraightLinePropagation 实现 |
| observer/ObserverSession.ts | 参考 / 本地时间积分、观察者状态、有限事件记录 |
| observer/SignalExperiment.ts | 单脉冲生命周期、远端时刻、移动接收者交会求解 |
| instruments/ObserverConsole.ts | 输入控件、双时钟、信号预测与抵达后的日志、信标投影 |
| instruments/ObservationPanel.ts | 继续提供几何读数和径向辐射模型图 |

未来叙事层应消费 ObservationEvent，区分仿真世界中的远端事件与本地已接收信息；不把剧情逻辑放进 Shader、时钟或输入模块。未来透镜成像可继续使用现有 ObserverState 和 VisualCore 边界。PropagationModel 当前契约适合确定性的传播时长；多重像、时变光路或多个到达事件需要扩展为路径/到达事件集合，不能只替换 travelTime 就声称获得完整透镜通信。

## 验证

- npm run build 通过；主 JS 646.51 kB，gzip 186.83 kB。保留 Vite >500 kB 包体提示，无新增依赖。
- 16 项测试通过。新增覆盖原轨迹复现、定点/恢复、视线与倍率边界、静止与运动时钟极限、积分收敛、因果事件顺序、防重复发射、跨长帧抵达、移动接收者解析对照。
- 实际浏览器验证鼠标点击定点/继续、拖动视线、回正、键盘视线和倍率控制；完成完整信号往返。
- 一次初始位置定点实验记录参考往返 8.747 s、本地往返 8.438 s；脉冲前后参考时间持续增加、平台速度为 0，符合定点模式语义。
- target 绘制缓冲区 1600×900：22 draw calls、6 geometries、17 textures，与 0.2 一致；没有新增 WebGL 绘制对象。
- 最终浏览器采样在 121.76 秒仍保持上述资源计数，Shader 错误 0，控制台无 error/warn；记录见 artifacts/prototype-0.3-runtime.txt。
- 与升级前压缩快照逐项 SHA-256 比对：10 个 GLSL 文件全部一致。
- 420×840 窄屏已目视检查：双时钟、定点/回正、倍率与发射按钮均可同时看到，仪器没有盖住主盘面；临时画幅覆盖已恢复。截图见 artifacts/prototype-0.3-mobile.png。
- 最终动态观测截图见 artifacts/prototype-0.3-preview.png。
- 开发设备验证不代表 RTX 4060 的最终帧率验收。GPU 计时与上下文恢复故障注入仍留待目标设备专项验证。

## 下一阶段建议

先完成 RTX 4060 上的持续运行与输入体验评估，再独立开发可量化验证的光路模型：静态 Schwarzschild 偏折、传播延迟及到达时刻。保持目前版本作为视觉和交互对照基线，统一时钟与信号模型之后再进入完整叙事设计。
